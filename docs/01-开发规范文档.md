# AI 协同开发规范文档

> 版本：v1.0　｜　适用范围：AI 多智能体协同完成"编程→测试→部署→交付"全闭环
> 本文档是整套框架的"宪法"，所有智能体、流水线、门禁都以此为准。

---

## 1. 总则

### 1.1 核心原则（四条铁律）

1. **职责分离**：写代码的智能体不得独自验收自己的代码。开发负责"造"，测试/安全/运维负责"验和交"。
2. **单一事实源**：所有状态、决策、产物都落在 Git 仓库 + 任务看板 + 文档目录。智能体是**无状态、短生命周期**的，不依赖"记忆"，只依赖仓库。
3. **最小权限**：每个智能体只拿完成本职责所需的最小工具权限和上下文。靠**工具/沙箱隔离**实现，而非靠提示词口头约束。
4. **门禁不可跳过**：缺陷不得流入下一阶段；任何门禁不通过即退回上一环节，人类审批点不可被自动化绕过。

### 1.2 人类介入点（最少干预原则）

人类全程只保留三个介入点：

| 介入点 | 时机 | 动作 |
|---|---|---|
| 定目标 | 流水线启动前 | 提供需求/目标、验收标准 |
| 关键门禁审批 | 架构评审、生产发布前 | 批准/驳回 |
| 最终验收 | 全部门禁通过后 | 验收交付物，发布 Release |

其余过程全部自动，人类不逐条看代码。

## 2. 角色定义（智能体清单）

| 角色 | 一句话职责 | 输入 | 输出 | 是否可改业务代码 |
|---|---|---|---|---|
| 编排器 Orchestrator | 拆任务、调度、检查门禁、重试 | 总目标 | 执行计划、门禁结果 | 否 |
| 需求/PM | 澄清需求、写验收标准 | 原始需求 | 需求文档、验收标准 | 否 |
| 架构师 | 技术选型、接口契约、架构图 | 需求文档 | 架构设计、API Spec | 否 |
| 前端 | 实现前端 + 单元测试 | 契约、设计 | 前端代码、单测 | 仅前端模块 |
| 后端 | 实现后端 + 单元测试 | 契约、设计 | 后端代码、单测 | 仅后端模块 |
| 代码评审 | 独立评审代码质量/安全 | PR | 评审意见、通过/驳回 | 否 |
| 测试 QA | 功能/UI/兼容/集成/性能测试 | 可运行产物 | 测试报告 | 否（只读+可执行测试） |
| 安全（红队） | 黑盒渗透、漏洞扫描、依赖审计 | staging 环境 | 安全报告 | 否 |
| 运维 DevOps | 部署、环境、可复用 runbook | 已验证产物 | 运行环境 + runbook | 否 |

> 关键区分：**单元测试**由对应开发智能体编写（边写边测），**集成/功能/UI/性能/安全测试**由独立测试/安全智能体实施。

## 3. 闭环流水线（10 阶段）

```
0 需求澄清 → 1 架构设计 → 2 任务拆解 → 3 并行编码 → 4 代码评审
   → 5 集成测试 → 6 安全测试 → 7 性能测试 → 8 部署 → 9 验收 → 10 交付
```

| 阶段 | 负责 | 产出物 | 门禁（自动校验） |
|---|---|---|---|
| 0 需求澄清 | PM | 需求文档、验收标准 | 含明确验收标准 |
| 1 架构设计 | 架构师 | 架构图、技术选型、API 契约 | 契约一致性检查 |
| 2 任务拆解 | 编排器 | Issue 列表、看板 | 任务可独立验收 |
| 3 并行编码 | 前端+后端 | 代码+单元测试 | lint/编译/单测覆盖率 |
| 4 代码评审 | 评审智能体 | 评审意见 | 无高危问题、评审通过 |
| 5 集成测试 | 测试 QA | 功能/UI/兼容报告 | 全部用例通过 |
| 6 安全测试 | 安全智能体 | 渗透/漏洞/依赖审计 | 无高危/严重漏洞 |
| 7 性能测试 | 测试 QA | 吞吐/延迟/并发报告 | 指标达标 |
| 8 部署 | 运维 | 运行环境 + runbook | 健康检查通过 |
| 9 验收 | 编排器+人类 | 交付报告 | 人类审批 |
| 10 交付 | 编排器 | Release/PR/CHANGELOG/文档 | 交付物完整 |

---

## 4. 门禁清单（Gate Checklist）

每个阶段结束必须执行的门禁，未通过则退回：

| 门禁 | 判定标准 | 失败动作 |
|---|---|---|
| 编译/构建 | 前端 build + 后端 build 成功 | 退回编码 |
| Lint/格式 | 无 error 级告警 | 退回编码 |
| 单元测试 | 覆盖率 ≥ 约定阈值，全通过 | 退回编码 |
| 代码评审 | 无高危问题，≥1 名评审通过 | 退回修复 |
| 功能/集成测试 | 用例 100% 通过 | 退回开发 |
| 安全扫描 | 无 Critical/High 漏洞 | 退回修复 |
| 性能测试 | 延迟/吞吐达标 | 退回优化 |
| 部署健康检查 | 存活/就绪探针通过 | 回滚并重试 |
| 人类审批 | 关键节点人工确认 | 终止或退回 |

## 5. 目录结构约定（每个项目统一）

```
project/
├── .gitignore
├── README.md                 # 项目说明 + 快速开始
├── docs/                     # 需求、架构、评审、测试、运维全部文档
│   ├── requirements.md       # 需求文档 + 验收标准
│   ├── architecture.md       # 架构设计 + API 契约
│   ├── review/               # 代码评审记录
│   ├── test/                 # 测试报告
│   └── runbook.md            # 运维实施文档（可复用）
├── frontend/                 # 前端（React 等）
├── backend/                  # 后端（Go/Python/Java/.NET 等）
├── tests/                    # 集成/功能/UI/性能/安全测试
├── deploy/                   # IaC：Dockerfile、Terraform、K8s 清单
├── .github/workflows/        # CI/CD 流水线
└── CHANGELOG.md              # 版本变更
```

## 6. 命名与提交规范

### 6.1 分支规范

```
main         # 受保护，仅通过 PR 合入
develop      # 集成分支
feature/*    # 功能分支
fix/*        # 修复分支
release/*    # 发布分支
```

### 6.2 提交信息（Conventional Commits）

```
<type>(<scope>): <subject>

type: feat | fix | docs | test | refactor | chore | perf | security
示例：feat(backend): 新增用户登录接口
      fix(frontend): 修复登录页表单校验
      test(api): 补充订单接口集成测试
```

### 6.3 产物命名

- 文档：`docs/<阶段>-<主题>.md`
- 测试报告：`docs/test/<日期>-<类型>-report.md`
- 交付：`Release vX.Y.Z` + `CHANGELOG.md`

## 7. 环境隔离规范（纯闭环，不碰生产）

### 7.1 三套环境分级

```
dev（开发自测） → staging（准生产，安全/性能/黑盒测试） → prod（生产）
                       ↑ 仅通过门禁 + 人类审批才可进入
```

### 7.2 五重隔离（硬性要求）

| 隔离维度 | 要求 |
|---|---|
| 环境隔离 | 一次性环境，从镜像 + IaC 全新建，用完即销毁 |
| 网络隔离 | 独立网段/云账号/Namespace，生产内网不连通 |
| 凭证隔离 | 独立测试凭证，生产密钥绝不注入测试环境 |
| 数据隔离 | 绝不连生产库/真实用户数据，用合成数据 + 脱敏 + 黄金数据 |
| 执行沙箱 | 所有命令/代码/测试在受限容器内运行（限网络/文件/资源） |

### 7.3 外部依赖替代

- 第三方 API（支付/短信等）→ 服务虚拟化 / Mock / WireMock / 契约测试。

---

## 8. 交付标准（Definition of Done）

一个阶段"完成"必须同时满足：

1. 对应门禁全部通过；
2. 产物已提交到 Git 仓库并关联 Issue；
3. 文档已更新（需求/架构/测试/运维）；
4. 可复现：任何人（任何智能体）可依据仓库从零重建。

最终交付物清单：**代码 + 测试报告 + 安全报告 + 性能报告 + 部署清单 + 运维 runbook + CHANGELOG + Release**。

---

## 9. 失败与回退策略

| 情况 | 策略 |
|---|---|
| 门禁不通过 | 自动退回上一环节，携带失败报告重跑，最多重试 N 次 |
| 重试仍失败 | 升级给编排器记录，暂停并通知人类 |
| 生产部署失败 | 自动回滚到上一稳定版本，保留现场日志 |
| 智能体跑偏 | 无状态智能体随时销毁重建，从仓库当前状态继续 |
