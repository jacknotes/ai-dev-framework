# 需求文档 — Java + Spring Boot 最小示例工程

> 版本：v0.1.0　｜　阶段：需求澄清（流水线阶段 0）　｜　负责人：需求/PM 智能体
> 门禁要求：每条功能需求必须有可判定的验收标准，否则不得进入架构设计。

## 1. 背景与目标

为 AI 多智能体协同开发框架提供一套 **Spring Boot 3.3 + Java 21** 的项目起点模板，与 `react-python`、`vue-go` 模板保持同一套目录约定与命令契约（`scripts/` 五个脚本）。

目标：复制该目录即可得到一个"能编译、能测、能部署、能探活"的最小闭环，验证流水线（编码 → 测试 → 部署 → 验收）在 JVM 技术栈上同样成立。

## 2. 用户故事

- 作为**最终用户**，我希望打开首页就能看到后端返回的问候语，以确认前后端已经联通。
- 作为**后端开发智能体**，我希望有清晰的分层与单测样例，以便按契约新增接口而不破坏既有行为。
- 作为**测试智能体**，我希望有独立的 `scripts/test.sh`，能一键跑完前后端单测并给出明确成败。
- 作为**运维智能体**，我希望后端有 `/health` 探针、前端有健康检查，能据此判断部署是否成功并决定是否回滚。

## 3. 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-1 | 后端健康检查接口 | P0 | `GET /health` 返回 200，响应体为 `{"status":"ok"}`；不依赖数据库或外部服务 |
| FR-2 | 后端问候接口 | P0 | `GET /api/v1/greeting` 返回 200，JSON 含 `message`（值为 `Hello from Java backend`）与 `time`（ISO-8601 UTC 时间串，可被 `Instant.parse` 解析） |
| FR-3 | 前端展示问候语 | P0 | 页面加载后请求 `/api/v1/greeting` 并渲染 `message`，同时展示 `time` |
| FR-4 | 前端展示后端健康状态 | P1 | 页面加载后请求 `/health`，正常时显示 `ok`，异常时显示 `不可用` 而非白屏 |
| FR-5 | 前端异常处理 | P1 | 问候接口失败时页面显示错误文案（含 HTTP 状态码），不出现白屏或未捕获异常 |
| FR-6 | 隔离环境一键启动 | P0 | `cd deploy && docker compose up -d --build` 后，`curl http://localhost:8000/health` 返回 200，前端 `http://localhost:80` 可访问 |
| FR-7 | 统一命令契约 | P0 | `scripts/{lint,build,test,health,e2e}.sh` 均存在且可执行；通过退出码 0 表示成功，非 0 表示失败 |
| FR-8 | 接口契约可机读 | P1 | `docs/api-spec.yaml` 为合法 OpenAPI 3.0.3，包含 `/health` 与 `/api/v1/greeting` 两个路径 |
| FR-9 | 运维文档可用 | P1 | `docs/runbook.md` 覆盖环境架构、依赖、构建、部署（含回滚）、监控、排障、备份、凭证 8 个小节 |

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 单实例（0.5 CPU / 512M）下 `/health` P95 < 50ms，`/api/v1/greeting` P95 < 100ms |
| 可用性 | 容器启动后 40s 内通过健康检查；健康检查失败 5 次判定为不健康 |
| 安全 | 容器以非 root 用户运行；根文件系统只读；`no-new-privileges`；无生产凭证 |
| 可维护性 | 后端单测覆盖两个接口的正常与异常路径；前端单测行覆盖率 ≥ 80% |
| 可复现性 | 任何智能体可仅凭仓库从零重建（Maven / npm / Docker 三条路径） |
| 可移植性 | JDK 21 + Maven 3.9 + Node 20 环境下无额外系统依赖 |

## 5. 范围之外（本期不做）

- 用户体系、鉴权、限流（模板保持无状态）。
- 持久化数据库与迁移脚本。
- 多环境配置中心、服务注册发现。
- 真实支付/短信等第三方集成（如后续需要，按规范 §7.3 用 Mock/服务虚拟化替代）。

## 6. 澄清问题与假设

| 编号 | 问题/假设 | 结论 |
|---|---|---|
| Q-1 | 后端端口是 8000 还是 8080？ | 定为 **8000**（与 `vue-go`/`react-python` 模板及脚本默认值一致），通过 `PORT` 环境变量可覆盖 |
| Q-2 | 前端 dev 端口？ | **3000**，Vite 代理 `/api`、`/health` 到 8000 |
| Q-3 | 是否需要数据库？ | 不需要，示例仅返回内存数据 |
| Q-4 | Java 版本能否降到 17？ | 模板固定 **21（LTS）**，如需降级须同步修改 `pom.xml` 与 Dockerfile 基础镜像 |
| Q-5 | 时间格式用本地时间还是 UTC？ | 统一 **UTC 的 ISO-8601**（`Instant.now().toString()`），避免跨时区歧义 |

## 7. 验收清单（交给人审批用）

- [ ] `scripts/lint.sh`、`scripts/build.sh`、`scripts/test.sh` 退出码均为 0
- [ ] `scripts/health.sh` 在服务启动后输出 `{"status":"ok"}`
- [ ] `docker compose up -d --build` 后两个容器均为 `healthy`
- [ ] 浏览器访问前端首页可见 `Hello from Java backend`
- [ ] `docs/api-spec.yaml` 与实际响应字段一致
